# Phase 4.5 — MVP Polish (спека и план)

**Дата:** 2026-05-11.
**Trigger:** Phase 4 frontend MVP смержен в `main` (`452c01c`); пользовательский ревью выявил 10 user-facing gaps, не блокирующих, но раздражающих в демо. Закрываем их перед Phase 5 production deploy — научник / комиссия не должны спотыкаться о native `confirm()`, отсутствие переименования и пустой timeline.

**Что НЕ в этой фазе:**
- Email verification (требует SMTP-инфраструктуры — Phase 6).
- User profile (firstName, lastName, avatarUrl) — требует schema migration + новый identity domain — Phase 6.
- Production deploy — Phase 5.

## 2. Что чиним (10 пунктов, в порядке нарастания сложности)

### 2.1 Textarea без resize + min-height *(5 мин)*

**Сейчас:** `<UTextarea :rows="N">` в TaskDrawer / CreateTaskModal / SprintCreateModal без фиксации размера → пользователь может его растянуть.

**Чиним:** в `app/app.config.ts` добавить global override:
```ts
textarea: {
  slots: {
    base: 'resize-none min-h-[120px]',
  },
},
```

Inline overrides по месту (`:rows="N"`) оставить — они теперь означают «стартовая высота», а ручной resize отключен.

**Файлы:** `app/app.config.ts`.

---

### 2.2 ConfirmDialog component *(30 мин)*

**Сейчас:** native `window.confirm()` используется в 5 местах:
- `pages/workspaces/[id]/boards/index.vue` — удаление доски
- `pages/workspaces/[id]/members.vue` — удаление участника
- `components/sprint/SprintCard.vue` — закрытие + удаление спринта
- `components/task/TaskDrawer.vue` — удаление задачи

**Чиним:** shared компонент + composable.

**Файлы:**
- `app/components/common/ConfirmDialog.vue` — `<UModal>` с slot для контента, кнопки «Отмена» + «Подтвердить» (`color` настраиваемый — error для destructive).
- `app/composables/useConfirm.ts` — promise-based API:
  ```ts
  const confirm = useConfirm()
  if (await confirm({ title: 'Удалить доску?', description: '…', confirmLabel: 'Удалить', confirmColor: 'error' })) {
    // ...
  }
  ```
- Заменить native `confirm()` в 5 местах на `useConfirm()`.

Под капотом: composable использует Vue's `h()` для рендера ConfirmDialog с teleport и возвращает promise resolved'ивающийся на click кнопки. Альтернатива — Pinia store с queue confirm-запросов. Беру promise-based т.к. локально проще читать.

### 2.3 Password confirm в RegisterForm *(10 мин)*

**Сейчас:** одно поле `password` без подтверждения.

**Чиним:**
- `app/components/auth/RegisterForm.vue`: добавить `confirmPassword` field в state + schema
- Zod `.refine`:
  ```ts
  const schema = z.object({...}).refine(
    (d) => d.password === d.confirmPassword,
    { message: 'Пароли не совпадают', path: ['confirmPassword'] },
  )
  ```
- При submit отправлять только `{ email, password }` на backend (он `confirmPassword` не ждёт).

**Файлы:** `app/components/auth/RegisterForm.vue`.

---

### 2.4 Toast notifications на SSE events *(20 мин)*

**Сейчас:** SSE приходит, vue-query invalidate'ит → данные обновляются, но user не уведомляется.

**Чиним:** в `useBoardSse` ловить событие, мапить в toast через `useToast()` Nuxt UI.

**Файлы:** `app/composables/useBoardSse.ts`. Map per-event-type:
- `task.created` → «Новая задача появилась на доске» (info)
- `task.moved` → «Задача перемещена» (info) — но только если другой actor (не показывать toast на свои же действия → нужна сверка с `authStore.user.id`; payload должен содержать actorId)
- `task.updated` → «Задача обновлена»
- `task.deleted` → «Задача удалена» (warning)

**Гочча:** backend payload может не содержать actorId — надо посмотреть. Если нет — фильтр «не свои события» не сделаем, либо запросим расширения payload (если решим).

### 2.5 Column delete UI *(20 мин)*

**Сейчас:** backend `DELETE /api/.../columns/[columnId]` есть, `useColumnsApi.remove` есть, в UI нет кнопки.

**Чиним:**
- `app/components/board/BoardColumn.vue` — добавить hover-меню (UDropdownMenu) на header колонки: «Удалить колонку».
- Только для admin+ (gate через prop `canManage`).
- При клике → `useConfirm()` → `remove.mutateAsync(column.id)`.
- На 409 (колонка не пустая) — показать понятную ошибку через `useToast()`: «Колонка не пуста, сначала перенеси задачи».

**Файлы:** `app/components/board/BoardColumn.vue`.

### 2.6 Опция skip default columns при создании доски *(20 мин)*

**Сейчас:** `createBoard` всегда seedит 4 колонки (Backlog, In Progress, Review, Done).

**Чиним:**
- Backend: добавить опциональный `seedDefaults: boolean` (default `true`) в `CreateBoardSchema` + `createBoard` сервис.
- Frontend: в `BoardCreateModal` добавить `<UCheckbox v-model="state.useTemplate" />` «Использовать шаблон Scrumban» (default checked). При unchecked — backend создаёт доску без колонок.

**Файлы:**
- Backend: `server/api/workspaces/[id]/boards/index.post.ts`, `server/services/boards.service.ts`.
- Frontend: `shared/types/board.ts` (`CreateBoardInput.seedDefaults?: boolean`), `app/components/board/CreateModal.vue`.

### 2.10 Workspace rename — **backend gap** *(40 мин: 20 backend + 20 frontend)*

**Сейчас:** `server/api/workspaces/[id]/` имеет только `.get.ts`. Нет PATCH или DELETE.

**Чиним:**

**Backend:**
- Новый endpoint `server/api/workspaces/[id].patch.ts` с zod схемой `{ name?: string }` (slug менять не даём — он URL-критичен).
- Новый сервис `updateWorkspace({ workspaceId, name, actorRole })` в `workspaces.service.ts` с `requireMinRole(actor, 'admin')`.
- Тест на 1-2 кейса (success + 403).

**Frontend:**
- `useWorkspacesApi`: добавить `update` мутацию.
- `WorkspaceSwitcher` или Members page — место для inline-edit названия workspace (admin+). Можно временно положить inline-edit на `/workspaces/[id]/members.vue` рядом с заголовком («Workspace: Acme Corp»).

**Файлы:**
- Backend: `server/api/workspaces/[id].patch.ts`, `server/services/workspaces.service.ts`, `tests/workspaces.e2e.test.ts` (расширить).
- Frontend: `shared/types/workspace.ts` (`UpdateWorkspaceInput` уже есть, не трогать), `app/composables/api/useWorkspacesApi.ts`, `app/pages/workspaces/[id]/members.vue` (inline rename) или новая `settings.vue` страница.
