Пользователь явно сказал: «буду читать md и пытаться все это понять, чтобы понимать самому — это очень важно». Это относится к UML-диаграммам, backend-терминологии и архитектурным понятиям.

**Why:** Магистр делает диплом для защиты, где ему придётся отвечать на вопросы по КАЖДОМУ решению. Если он не понимает, что на диаграмме — он не сможет защититься, даже если она красивая. Чёрный ящик = провал.

**How to apply:**
- В MD-документах использовать простой русский, избегать жаргона без объяснения.
- Каждый незнакомый термин (RLS, event sourcing, SSE, middleware, Drizzle, pg-boss, Caddy, cycle time, etc.) — явно объяснять в 1–2 предложениях при первом упоминании.
- Добавлять «в человеческих терминах» пояснения: «что это значит для пользователя / для кода».
- Предпочитать 3 простых диаграммы перед 1 сложной, если это помогает пониманию.
- Давать время на чтение между крупными блоками работы — не перегружать сессию.
- В глоссариях сопровождать термин английским оригиналом (для гугла) и русским пояснением.
- По запросу пользователя пробовать переписать любой фрагмент более понятным языком («объясни X как для 5-классника»).
- НЕ давить темпом. Если пользователь сказал «буду разбираться» — значит хочет паузу на усвоение.
